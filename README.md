## 背景:这类水印是怎么回事

很多在线简历 / 文档生成器(如 CodeCV 一类)在导出 PDF 时,会用 PDF 的 **平铺图案(Tiling Pattern,`PatternType 1`)** 机制把一张水印图片(或水印文字)平铺铺满整页。

这类水印有三个典型特征,导致常规去水印手段全部失效:

1. **文字层搜不到** —— 用 `page.search_for("水印文字")` 返回空,因为水印不在文字对象里,而是被封装在一个 Pattern 对象中。
2. **不是单张普通贴图** —— 它不是页面上的一张 image,删图片删不掉,而是 Pattern 内部通过 `Do` 指令引用的 XObject。
3. **被当成"填充色"铺满整页** —— 页面内容流里用 `/Pattern cs  /Pxx scn`(设置图案为当前填充色),再画一个覆盖全页的矩形 `0 0 794 3672 re  f` 把图案铺开。

本工具正是针对这一机制设计的。

---

## 工作原理

一句话:**找到所有"用来铺水印"的平铺图案,把它们的内容流清空,让它们绘制"空"。**

具体分三步:

1. **扫描** — 遍历 PDF 所有间接对象,筛出 `/PatternType 1` 的平铺图案对象,记录它是否绘制了 XObject(`... Do`)或文字(`Tj`/`TJ`)。
2. **确认** — 对每个候选图案,反查哪些页面的资源字典引用了它,并检查该页内容流是否用 `/Pxx scn`(或 `SCN`)把它当作填充色使用。只有"绘制了内容"且"被当填充铺开"的,才判定为水印。
3. **清空** — 用 `doc.update_stream(xref, b" ")` 把该图案的内容流替换成一个空格。图案对象、页面结构、引用关系都保留,但它渲染时不再画任何东西。

因为正文、照片、字体、超链接都存放在**其他独立对象**里,清空图案内容流不会波及它们,所以"只去水印、不动其余内容"。

## 适用范围与局限

### ✅ 适用

- 用 **平铺图案(PatternType 1)铺满整页** 的水印,无论水印内容是图片还是矢量文字。
- CodeCV 及同类在线简历 / 文档生成器导出的 PDF,大多属于此类。
- 多页 PDF,每页可以是不同的图案对象,工具会逐一识别。

### ⚠️ 不适用(工具会提示"未发现平铺图案类水印",不会误改文件)

- 水印是**直接写在正文内容流里**的文字或贴图。
- 水印是 **Annotation(注释)** 形式。
- 水印被**烧进了页面背景位图**(整页扫描成一张图)。
- 使用 **渐变图案(`PatternType 2`)** 的情况——工具刻意不动它,避免破坏正常的渐变填充效果。

以上情况需要按其具体承载方式另行处理(删文字层 / 删注释 / 图像修复等)。

## 使用方法

### 1. 直接去水印(最常用)

```bash
//linux
python3 remove_pattern_watermark.py input.pdf output.pdf
//win
PS D:\codecv_clean\src> python .\remove_pattern_watermark.py ..\test\test.pdf ..\test\output.pdf
```

### 2. 省略输出文件名(自动生成 `*_clean.pdf`)

```bash
python3 remove_pattern_watermark.py input.pdf
# 输出: input_clean.pdf
```

### 3. 先预览,确认无误再执行(推荐第一次使用时先跑)

```bash
python3 remove_pattern_watermark.py input.pdf --dry-run
```

`--dry-run` 只打印将要清空哪些图案对象,**不写出任何文件**。

### 4. 手动指定只清空某几个图案对象

当自动判定不符合预期(漏清或误清)时,可用 `--dry-run` 看到每个图案的 xref 编号,再手动指定:

```bash
python3 remove_pattern_watermark.py input.pdf output.pdf --only 130,153
```

## 判定逻辑详解

对应源码中的两个核心函数:

- **`find_pattern_xrefs(doc)`**
  遍历 `xref` 表所有对象,保留 `/PatternType 1`(平铺图案)。对每个图案读取其内容流,用正则判断:
  - `draws_xobject`:是否含 `\w+\s+Do`(绘制了 XObject,通常就是水印图)
  - `draws_text`:是否含 `Tj` / `TJ`(绘制了文字)

- **`pattern_is_used_as_fill(doc, xref)`**
  在每一页的资源字典里查 `/Pname xref 0 R` 找出该图案在页面中的资源名,再在页面内容流里检查是否存在 `/Pname scn` 或 `/Pname SCN`。命中即说明该图案被当作填充色铺开——这是"铺满整页"水印的判定依据。

**自动判定条件(两者同时满足)**:`(draws_xobject 或 draws_text)` **且** `被当作填充铺开`。
使用 `--only` 时,跳过上述自动判定,严格只清空你指定的 xref。

清空动作:`doc.update_stream(xref, b" ")`;保存时使用 `garbage=4, deflate=True, clean=True` 做垃圾回收与压缩,尽量减小体积、清理无用引用。

## 常见问题 FAQ

**Q1:清空后水印图片对象还在文件里,会不会泄露?**
清空的是"图案的绘制指令",水印图 XObject 对象本身可能仍存在于文件中(只是不再被任何地方绘制)。保存时 `garbage=4` 会回收不再被引用的对象;若担心残留,可再用 PDF 工具做一次彻底重写。

**Q2:提示"未发现平铺图案类水印"怎么办?**
说明这份 PDF 的水印不是平铺图案类型(见[适用范围与局限](#适用范围与局限))。此时文件不会被修改,需要针对其真实承载方式另行处理。

**Q3:自动判定漏清 / 误清了怎么办?**
先用 `--dry-run` 看到所有图案及其 xref 与内容预览,再用 `--only` 精确指定要清空的对象。

**Q4:会改变正文、排版、字体、图片、链接吗?**
不会。工具只清空被判定为水印的图案对象内容流,其余对象一律不动。

**Q5:一次能处理多个 PDF 吗?**
脚本单次处理一个文件。批量可用 shell 循环:
```bash
for f in *.pdf; do python3 remove_pattern_watermark.py "$f"; done
```

## 安全性说明

- 工具**不联网**,纯本地处理,不上传任何文件。
- 建议在**副本**上操作,或保留原始 PDF;工具默认输出到新文件(`*_clean.pdf`),不会覆盖原文件(除非你把 `output` 显式指定为输入同名路径)。
- 请仅对**你有权处理的文档**去除水印,遵守相应版权与合规要求。
